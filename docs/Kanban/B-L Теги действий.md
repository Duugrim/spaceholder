# Теги действий

Источник: ответ владельца 2026-10-29 при работе над [[A-L Состояния цели для сопротивления попаданию]].

Нужна классификация действий по тегам: какие из них прерывают движение (статус «Движется»), а какие нет — и, возможно, другие свойства. Отдельная система, не часть статусов.

## Как сейчас

Любое действие, кроме перемещения, снимает «Движется»: событие `action` (`STATUS_EVENTS.ACTION`) приходит из `announceCombatAction` — его зовёт `logCombatAction` (каждое действие, записанное в лог боя) и каждый выстрел (`aiming-manager`). Статус подписан на событие целиком, без разбора.

## Решить

- Словарь тегов и где они хранятся: у действий (`action-service`), шагов цепочки атаки, режимов оружия.
- Как статус называет, что его снимает: сейчас `endOn: ['action']`; с тегами — например, «любое действие с тегом X». Событие должно нести теги действия.
- Какие действия движение не прерывают — решает владелец.

Не путать с карточкой «Переименовать теги предмета в функции предмета» (теги предмета, не действия).
