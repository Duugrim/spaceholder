Глобальная карта, хронология, события, глобальные объекты и очки прогресса выносятся из системы в отдельный модуль **Азимут** (`E:\FoundryVTT\Data\modules\azimuth`, свой git-репозиторий). Образец — [[B-XL Модуль иконок — вынос из системы]]. Карточка [[C-XL 3D-рельеф глобальной карты]] переезжает вместе с кодом.

## Решения владельца (2026-10-26)

- Название «Азимут», в `title` по-английски: **Azimuth**. Id Foundry допускает только `A-Za-z0-9-_` (проверено в `base-package.mjs`), поэтому id — `azimuth` (подтверждено). Приставок `sh-`/`spaceholder-` нет: модуль самостоятельный и должен загружаться в любом мире.
- Локализация: английский и русский, обе полные (`lang/en.json`, `lang/ru.json`); любая строка интерфейса идёт через i18n.
- Описание в `module.json` — на английском и со словами **World Building**, чтобы модуль находился в браузере модулей. Черновик: «A World Building toolkit for campaign-scale play: a global strategic map with biomes and 3D terrain, a world timeline, events, factions and progression points. Integrates more deeply when used with the SpaceHolder system.»
- Система и модуль узнают друг друга и работают как единое целое (2026-10-27): слой интеграции двусторонний. Модуль включает свою половину, если `game.system.id === 'spaceholder'`; система — свою, если модуль `azimuth` активен. Состав — в разделе «Слой интеграции».
- Фракции в мире SpaceHolder — системные (`faction`), модуль работает на них; свои `azimuth.faction` он там не использует (2026-10-27). Выключение модуля фракции не трогает. В остальных системах работает `azimuth.faction`.
- Зоны влияния: код `influence-manager.mjs` остаётся в системе, потому что подключится к новым источникам позже. Все пути включить влияние из самой системы (не через модуль) убираем при переезде.
- Совместимость со старыми мирами не нужна: актёров `globalobject`, флаги и настройки не мигрируем.
- Оформление листов модуля — стандартный Foundry, без темы системы SpaceHolder: «так даже лучше» (2026-10-26). Стили системы в модуль не тащим.
- Тип `globalobject` из системы уходит целиком, без переходного периода: в старых мирах такие актёры станут невалидными, не конвертируем (2026-10-27).
- Очки прогресса — необязательная часть модуля и уходят из системы вместе с остальными частями Азимута, включая поля `ppModifier`/`ppSpends` системной фракции (2026-10-27).
- В мире SpaceHolder обе кнопки создания в шапке вкладки «Акторы» скрыты: диалог создания системы показывает модульные типы сам (2026-10-27).

## Слой интеграции с SpaceHolder (состав согласован 2026-10-27)

Двусторонний. Каждая сторона проверяет, что вторая на месте (`game.system.id === 'spaceholder'` в модуле, `game.modules.get('azimuth')?.active` в системе), и обе несут номер версии интеграционного API, чтобы предупредить о несовместимости. Правило разделения: **система спрашивает у модуля то, что принадлежит модулю** (источники влияния, «чей этот журнал»); **модуль добавляет в систему то, что относится к интерфейсу системы** (кнопки, слот листа, реестры типов). Свои половины: в модуле `scripts/integrations/` (на `init`), в системе `module/helpers/azimuth-link.mjs` (на `ready`).

**Модуль в мире SpaceHolder**
- Фракции: `isFactionActor()` в одном месте, набор типов `['faction']` вместо `['azimuth.faction']` (в коде около 25 мест с проверкой типа). Поля `fColor`, `fLink` у системной фракции те же, превью и цвета работают как есть. Поле фракции у объекта Азимут принимает системную фракцию.
- Привязка пользователей к фракциям: единый источник — `flags.spaceholder.factions` (на нём бои, кучи предметов, шапка персонажа). Модуль читает и пишет туда же; своя панель в настройках пользователя скрыта.
- Создание: обе кнопки в шапке вкладки «Акторы» скрыты; `azimuth.faction` добавлен в скрытые типы диалога создания системы, объект Азимут выбирается в нём как обычный тип.
- Очки прогресса системных фракций: `ppModifier`/`ppSpends` лежат во флагах `flags.azimuth.pp`, чтение и запись через один доступ (`azimuth.faction` в других системах хранит их в `system`). Блок очков модуль выводит в слот листа фракции системы.
- Влияние: `game.azimuth.getInfluenceSources()` отдаёт источники, кнопки показа влияния на панели края и в хотбаре работают только в этом режиме; хуки на токены и актёров объектов живут в модуле и просят `requestRedraw()`.
- Хотбар: одна группа кнопок (по умолчанию), модуль добавляет в системную хронологию, события, индикатор очков, влияние; свой блок хотбара в этом мире не рисует.
- Статус страниц для очков прогресса: `setPageStatusProvider` берёт `getStatus` из системного `journal-check`.
- Служебные журналы: `isServiceJournal(doc)` (хронология и события).
- Указатель токена: добавляет `azimuth.globalobject` в реестр типов без указателя.

**Система при активном модуле** (`azimuth-link.mjs`)
- Подключает провайдера влияния: `InfluenceManager` берёт источники у `game.azimuth`.
- Журнал: спрашивает `game.azimuth.isServiceJournal(doc)` и пропускает такие журналы.
- Даёт слот листа фракции и реестр кнопок хотбара, показывает их содержимое модуля.

**Порядок**

- Лист фракции: `registerFactionSheetSection` — разметка раздела идёт внутрь формы листа, `activate` оживляет её после каждой отрисовки; собственный блок очков системы остаётся до этапа 4.

Мутационные проверки: восемь поломок (обе стороны) ловятся.

## Как устроен перенос (этап 2)

Код скопирован скриптом с механическими заменами, потом правился руками; системные файлы не менялись.

- **Раскладка.** `scripts/helpers/*` повторяет `module/helpers/*` системы (внутри `global-map/` и `global-map/terrain3d/`), `scripts/vendor/three.module.mjs`, `templates/`, `src/scss/`, `data/globalmaps/`, `docs/`. Вход — `scripts/azimuth.mjs` (повторяет регистрации из `spaceholder.mjs`).
- **Пространство имён.** Флаги, настройки и сокет — `azimuth` (сокет `module.azimuth`, в `module.json` `"socket": true`). Классы, id и переменные CSS — `azimuth-*`. Окна модуля несут класс `azimuth-app`: на нём тёмная тема, листы актёров его не получают и остаются стандартными. API — `game.azimuth`, он же `game.modules.get('azimuth').api`. Типы актёров — через `ACTOR_TYPES`.
- **Стили.** Из системы взяты только нужные части: переменные и тема окна (`_theme.scss`), поля форм (`base/_forms.scss`), стили переносимых окон. Сборка: `npm run build` (нужен `sass`, пока можно собирать sass-ом системы).
- **Отличия от системного кода:**
  - выбор иконки (хронология): Iconic, если включён, иначе файловый выбор Foundry (`helpers/icon-pick.mjs`);
  - цвет фракции в панели края берётся из `fColor` фракции (`helpers/faction-color.mjs`), а не из менеджера влияния;
  - хотбар без кнопок «журнал изменений» (это функция системы) и «влияние» (слой интеграции); индикатор PP, хронология, очки и события на месте;
  - листы: поля PP показываются, только если очки прогресса включены в настройках модуля (как в системе);
  - не перенесено: быстрые настройки токена в шапке листа объекта (привязка актёра, имя токена, зрение; штатный пункт «Настроить токен» в меню листа есть), `globalobject-actors.mjs` (его хуки не подключались и в системе);
  - опция операций `azimuthJournalCheck` оставлена по образцу системной `spaceholderJournalCheck`, но система её не знает: нужен нейтральный механизм (этап 4).
- **Пока дублируется в мире SpaceHolder** (до этапа 4): карта и её панели, хронология, события, PP, панель фракции в хотбаре, панель фракций в настройках пользователя. У копий разные флаги и настройки, сцену нужно помечать отдельно. Поэтому проверять лучше в мирах PF2e и dnd5e, где дублей нет.
