# SpaceHolder: Руководство по дизайну интерфейса

Документ описывает предпочтительные паттерны и правила дизайна UI системы SpaceHolder. Используйте его при доработках интерфейса — как справочник для себя и как контекст для AI-агентов.

**Источник:** анализ эталонных экранов + заметки автора (2025).

---

## 1. Принципы дизайна

### 1.1 Минимализм — без лишнего текста

**Правило:** Избегать избыточных заголовков, надписей, подписей и подсказок.

- Если мы во вкладке «Инвентарь» — не нужен ещё и заголовок «Инвентарь» (это уже в названии вкладки).
- Один заголовок секции достаточен; дублирование только путает.
- **Подсказки допустимы**, когда добавляют смысл. Но нельзя перегибать:
  - ❌ Чекбокс «Включение перемещения» + tooltip «Включение перемещения» + подпись «Включает перемещение».
  - ✅ Чекбокс с иконкой + tooltip «Включает режим перемещения на карте» (если нужно уточнение).
  - ✅ Иконка без текста + tooltip с расшифровкой — хороший вариант.

**Эталон:** Характеристики (один заголовок секции), Инвентарь (заголовок + данные без дублирования), Настройки карты (лаконичные лейблы).

### 1.2 Иконки вместо надписей

**Правило:** Предпочитать иконки там, где они универсально понятны и экономят место.

- Иконки короче текста, работают в любом языке.
- Если иконка может быть непонятна — добавляем tooltip.
- **План (Инвентарь):** убрать «Общий вес» и «Предметов», оставить иконки + tooltip с текстом.

**Эталон:** Кнопки-действия в Ивентах (edit, delete, resolve и т.д.), иконки в настройках карты (leaf, circle-half-stroke, eye-slash и т.д.), иконка в заголовке «Характеристики» (fa-dumbbell).

### 1.3 Селекторы вместо выпадающих списков

**Правило:** Использовать группы кнопок (селекторы), а не `<select>` / dropdown, где это уместно.

- Селектор показывает все варианты сразу, не требует раскрытия.
- Удобнее на мобильных и при небольшом числе опций (2–7).

**Эталон:** Настройки карты (модуль Azimuth: `templates/global-map/edge-panel.hbs`) — Биомы, Высоты, Реки, Поворот подписи, Регионы, Сглаживание (0–4), Анимация появления — все реализованы как группы icon-btn или числовых кнопок.

**Исключение:** Ивенты — фильтры «Фракция», «Статус», «Сортировка» используют dropdown. Это считается менее идеальным вариантом; при рефакторе стоит рассмотреть селекторы.

### 1.4 Акцентные цвета

**Правило:** Использовать акцентные цвета для выделения активного состояния и важных элементов.

- Цвет не обязан быть зелёным — он должен быть контекстно уместен.
- Зелёные заголовки секций (section-header) — один из вариантов, не обязательный для всех секций.
- Акцент помогает обозначить: выбранное значение, активная кнопка, действие по умолчанию, статус (например, orange для «не выбрано», blue для «действие»).

**Эталон:** Анатомия (оранжевый статус «не выбрано», синяя кнопка «Выбрать»), Настройки карты (зелёная подсветка активной кнопки в группе), заголовки Характеристики/Инвентарь (зелёный блок).

### 1.5 Блоки и кнопки-иконки

**Правило:** Использовать скруглённые углы для внутренних блоков, карточек, кнопок - везде, где в любом случае нужен отступ. Основные контентные блоки не скругляем и стыкуем друг к другу для экономии места.

- Современный, мягкий визуальный стиль, экономящий место.
- Кнопки-иконки — компактный способ действий; текст — только при необходимости.

**Эталон:** Ивенты (кнопки edit/delete/history, карточки событий), Анатомия (рамка, кнопки), Настройки карты (все элементы), Характеристики (блоки аббревиатур и значений).

**Плотность:** меньше отступов и «островков», больше плотной сегментации — соседние элементы стыкуем в один блок и разделяем тонкими линиями/подложками, а не рассыпаем отдельными карточками с зазорами.

### 1.5.1 Подсказки (tooltip)

**Правило:** подсказка говорит, **что это за элемент**, а не что с ним делать. Коротко: название (+ цена ОД и т.п. для иконок без текста).

- ✅ «Перезарядить (20 ОД)», «Действия оружия», «Снять выбор».
- ❌ «Клик — выбрать для атаки, перетащите на хотбар — ярлык атаки», «(также ПКМ)».
- Инструкции по жестам (перетаскивание, ПКМ) в подсказки не пишем.

### 1.6 Геометрия вкладок (персонаж и предмет)

**Правило:** Вкладки primary-листов (`sheet-body--character-primary`, `sheet-body--item-primary`) собираем как единый прямоугольный контент без локальных исключений по конкретным tab-id.

- Активная `.tab` в primary-вкладках — без внутреннего `padding`; внутренние отступы задаются только контентными блоками.
- Баннер вкладки (`.sh-tab-banner`) стыкуется с рамкой вкладки без горизонтальных сдвигов и без точечных `margin-left/right` фиксов.
- Верхние управляющие ряды (как выбор анатомии/покрытия) всегда оформляются отдельным прямоугольным блоком с фоном и рамкой.
- Не использовать паттерн "исправить только `description`/`melee`/...": сначала правим общий контейнер primary-вкладок, потом локальный контент.

**Эталон:** `Характеристики`, `Анатомия`, `Инвентарь`, `Травмы` у персонажа; `Описание`/`Покрытие` у предмета с той же базовой геометрией.

### 1.7 Лист — для тонкой настройки, быстрый HUD — для обычной игры

**Цель:** лист персонажа открывают, чтобы настроить что-то тонко (характеристики, анатомию, навыки, предмет). Всё обычное — атака, перезарядка, смена режима, взять в руки, надеть/снять, найти простой предмет — должно делаться из быстрого HUD, а в идеале и полностью без листа.

- Новые «повседневные» функции сначала проектируются под HUD, лист получает их как зеркало или не получает вовсе.
- Общие списки действий (вкладка «Действия», быстрые действия HUD) — для особых действий с предметами. Простые действия, которые есть у каждого предмета (снять, убрать, выбросить, показать), в них не попадают, пока не добавлены в избранное; добавляются они из блока «Действия с предметом» в превью инвентаря.
- Направление развития HUD (карточка «Быстрый HUD — расширение»): блок с портретом и состояниями слева, сворачиваемый; быстрый инвентарь справа, сворачиваемый (короткие строки, мелкие иконки, фильтр по типам); почти весь нижний центральный блок — под действия.

## 2. Эталонные экраны и код

### 2.1 Характеристики (Stats)

- **Назначение:** Отображение основных статов (END, STR, AGI, COR, PER, INT, LUC) и модификаторов.
- **Дизайн:** Секция с зелёным заголовком (иконка + текст «Характеристики»), ряды: аббревиатура (скруглённый бейдж) + полное название + значение + модификатор.
- **Код:**  
  - Шаблон: `templates/actor/actor-character-sheet.hbs` (tab stats, `.stats-panel`, `.section-header`, `.capacities-list`, `.capacity-line`).  
  - Стили: SCSS с префиксом `spaceholder-` / `.section-header` и т.п.

### 2.2 Инвентарь (Inventory)

- **Назначение:** Список предметов, статистика (вес, количество), пустое состояние.
- **Дизайн:** Зелёный заголовок с иконкой рюкзака, строки статистики (иконка + текст; планируется замена текста на tooltip), кнопка «+ Новый предмет», пустое состояние — иконка коробки + подсказка.
- **Код:**  
  - Шаблон: `templates/actor/parts/actor-inventory.hbs`.  
  - Локализация: `lang/ru.json` (SPACEHOLDER.Inventory.*).

### 2.3 Ивенты (Events)

- **Назначение:** Управление черновиками и событиями фракций.
- **Дизайн:** Табы (Черновики / События фракций), фильтры (сейчас dropdown — кандидат на селекторы), список событий, панель деталей с кнопками-иконками (reply, resolve, edit, timeline, mark finished, delete).
- **Замечание:** Экран «не до конца нравится», но служит примером кнопок-иконок и скруглённых блоков.
- **Код** (окно переехало в модуль Azimuth, `Data/modules/azimuth`):  
  - Шаблон: `templates/events/events-app.hbs`.  
  - Стили: `src/scss/components/_events.scss` (в модуле); `_journal-check.scss` — в системе.

### 2.4 Настройки карты (Global Map Edge UI)

- **Назначение:** Видимость биомов, высот, рек, регионов, сглаживание, анимация появления.
- **Дизайн:** Лейбл слева, справа — группа icon-btn (или числовых кнопок для сглаживания). Активная кнопка — зелёный фон. Все элементы скруглены.
- **Код** (панель переехала в модуль Azimuth, `Data/modules/azimuth`):  
  - Шаблон: `templates/global-map/edge-panel.hbs` (flyout справа — `.azimuth-gm-edge__flyout--right`).  
  - Стили: `src/scss/components/_globalmap-edge-ui.scss`.  
  - Код: `scripts/helpers/global-map/*`.

### 2.5 Анатомия (Health tab)

- **Назначение:** Части тела, выбор/сброс анатомии.
- **Дизайн:** Секция «No body parts data available» при отсутствии данных; блок «Анатомия:» с двумя элементами: статус (оранжевый) и кнопка «+ Выбрать анатомию» (синяя). Пример дифференциации акцентных цветов.
- **Код:**  
  - Шаблон: `templates/actor/parts/actor-health.hbs` (`.anatomy-management-container`, `.current-anatomy`, `.no-anatomy`, `.anatomy-toggle-btn`).  
  - Логика: `module/sheets/actor-sheet.mjs`, `module/anatomy-manager.mjs`.

### 2.6 Менеджер действий ГМа — плашка статуса и окно очереди

**Эталон «чистого ровного» дизайна.** Файлы: `src/scss/components/_gm-actions.scss`, `module/helpers/gm-actions/gm-action-chat.mjs`, `templates/gm-actions/queue-dialog.hbs`.

Плашка «Действие ожидает ГМа» (в чате):

- Это строка внутри сообщения, на которое указал вызывающий (`chatMessageId`): дописывается при отрисовке по флагу и сама исчезает, когда ГМ применил действие. Состояние живёт в данных, а не в тексте. Если сообщения нет (выстрел его не передаёт), заметка — отдельное маленькое сообщение.
- Одна строка на статус, число вынесено в текст («Действия ожидают ГМа (3)») — три выстрела не дают три плашки.
- Цвет несёт смысл и задан **одним токеном на статус**: рамка слева 3 px, иконка и текст берут `currentColor` — ожидает (`$sh-warning`), отменено (`$sh-text-dim`), ошибка (`$sh-danger`). Никаких отдельных цветов для фона, рамки и иконки.
- Фон — не серая плашка другого оттенка, а 5% белого поверх родителя; скругление только справа (`0 3px 3px 0`), слева прямая рамка-акцент.
- Мелко и плотно: 11 px, вес 600, отступы 3×8, иконка Font Awesome 11 px перед текстом. Без кнопок и без инструкций.

Окно очереди («Действия игроков в ваше отсутствие»):

- Группы — **стыкованные сегменты**: один блок с рамкой 1 px и радиусом 4 px на категорию, заголовок-полоса (6% белого) с чекбоксом, названием и счётчиком-«таблеткой», строки разделены тонкими линиями, без зазоров между строками.
- Строка = чекбокс · время (`tabular-nums`, приглушённое) · имя игрока (акцентное, жирное) · описание. Больше ничего.
- Всё отмечено по умолчанию: типичный случай («применить всё») — один клик, исключения снимаются галочкой. Группа переключает все свои строки.
- Наведение — едва заметные 4% белого; текст 12 px; высота ограничена (60vh) с прокруткой.

Что переносить в другие экраны: один цветовой токен на состояние (`currentColor`), плотные стыкованные сегменты вместо россыпи карточек, счётчики в тексте вместо дублей, значения по умолчанию, при которых частое действие — один клик, и никакого дублирования подписей.

## 3. Структура стилей

- SCSS: `src/scss/` → `css/spaceholder.css` (после `npm run build`).
- Компоненты: `src/scss/components/_*.scss`.
- Префиксы: `spaceholder-`, `sh-` (например, `sh-events__`, `sh-gm-edge__`).
- Общие классы: `section-header`, `icon-btn`, и т.д. — см. эталонные шаблоны.

---

## 4. Антипаттерны (чего избегать)

1. **Тройное дублирование:** чекбокс + tooltip с тем же текстом + подпись.
2. **Лишние заголовки:** заголовок секции, когда контекст уже ясен из вкладки или соседних элементов.
3. **Dropdown вместо селектора:** когда вариантов мало (2–7) и они фиксированы — лучше группа кнопок.
4. **Текст вместо иконки:** для действий (edit, delete, add) и повторяющихся меток — предпочтительны иконки + tooltip.
5. **Подсказка-инструкция:** tooltip с описанием жестов вместо названия элемента (см. 1.5.1).
6. **Одинаковый акцент везде:** не нужно делать все заголовки только зелёными блоками; использовать другие цвета, где применимо, или не использовать вовсе.

## 5. Использование этого документа

- При разработке новых UI-блоков — сверяться с принципами и эталонами.
- Для AI-агентов — добавлять в контекст (например, через `.cursorrules` или `AGENTS.md`) ссылку на этот документ при задачах, связанных с интерфейсом.
- Документ можно дополнять новыми скриншотами и уточнениями по мере эволюции дизайна.
