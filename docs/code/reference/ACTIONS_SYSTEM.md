# Actions System (MVP)

Этот документ описывает новую подсистему **Действий** (Actions) в SpaceHolder.

## Цели MVP

- Единый слой, который позволяет **любой сущности** (Actor/Item/система) добавить актёру действие.
- Возможность **фильтровать действия по контексту** (например, скрывать в бою).
- Базовый ресурс **Очки Действия (ОД)** у персонажа (Character) и списание при выполнении действий.
- Боевая интеграция: таблицы действий по участнику/раунду, стороны конфликта, события боя.
- Движение через core Foundry v13 (`TokenDocument.movement`) с автоматическим логированием в бою.

## Что MVP не делает

- Полные реплеи боя (есть только foundation для перемотки/undo).
- Овердрафт ОД в бою (уход в минус с согласия ГМа или по параметру персонажа) — в бою ОД жёстко ограничены, см. `COMBAT_SYSTEM_V1.md` («AP rules»).

## Данные (schema)

Источник истины — `template.json`.

- `Actor.character.system.gFaction`: постоянная фракция персонажа (UUID Actor(faction)).
- `Actor.character.system.speed`: скорость (если `<= 0`, действие «Движение» недоступно).
- `Actor.character.system.actions[]`: кастомные действия персонажа.
- `Item.*.system.actions[]`: кастомные действия предмета.
- `Item.item.system.defaultActions`: флаги видимости стандартных «Надеть/Снять».

## Контракт действия (runtime)

Сервис строит список `ActionDescriptor` и отдаёт его UI/панелям.

Ключевые поля:

- `id`: стабильный идентификатор действия (используется UI).
- `label`: отображаемое имя (i18n или user-defined).
- `apCost`: базовая стоимость в ОД (для большинства действий списывается сразу; для движения — при confirm). Списывается `getEffectiveActionCost` — с поправкой на скорость действий (COR: `applyActionSpeedToCost`, 100 → ×1, 200 → ×0.75). Во всех списках и подсказках показывается та же цена: `actionApShown(actor, action)`.
- `showInCombat`, `showInQuickbar`: фильтры видимости. `showInQuickbar === false` — действие не показывается в быстром HUD токена (лист персонажа его не читает); избранное закрепляется в HUD, даже если `showInQuickbar === false`.
- `basic`: простое действие, которое есть у каждого предмета (надеть/снять, взять в руки, убрать, выбросить, показать). Базовые цены — `CONFIG.SPACEHOLDER.itemActionAp` (`hold` 10, `stow` 5, `equip` 20, `unequip` 10, `drop` 5, `show` 2; значения стартовые), читает `_itemActionAp`. В общие списки (вкладка «Действия», быстрые действия HUD) попадает только если добавлено в избранное — `listableActions(actions, favoriteIds)`. Добавляют в избранное из блока «Действия с предметом» в превью инвентаря (звёздочка у каждого действия).
- `interactMenuOnly`: только в меню ПКМ предмета (`openItemInteractMenu`), не в списках действий.
- `uiOnly`: UI-переключатель, а не игровое действие — `executeActorAction` вызывает `run` без ОД, старта хода и журнала (пример: «быстрый доступ»).
- `previewApCost`: стоимость для показа в меню, когда `run` сам списывает ОД (у дескриптора `apCost` = 0; пример: смена режима стрельбы).
- `visible(ctx)`, `enabled(ctx)`, `disabledReason(ctx)`: условия доступности.
- `run(ctx)`: выполнение.

Реализация: `module/helpers/actions/action-service.mjs`.

## Источники действий (providers в MVP)

Сейчас сервис собирает действия из:

- **Base actor actions**: `Движение` для `character` при `speed > 0`.
- **Предмет (тип `item`)**: стандартные `Надеть/Снять` только если `item.system.itemTags.isArmor === true`, в зависимости от `item.system.equipped`.
- **Custom actions**: `actor.system.actions[]` и `item.system.actions[]` (для предметов — только при `item.system.itemTags.isActions === true`).
- **Оружие v3**: в общих списках действий нет ничего («Взаимодействовать» убрано: оно дублировало ПКМ по предмету). Атака **не является действием**: это возможность предмета `item.canAttack` / `item.attack({ token })` (`module/helpers/weapon/attack-chain.mjs`: `canAttackWithItem`, `attackWithItem`, `previewItemAttack`). Атака идёт активными линией/режимом из `system.weapon.state`.
  - **Цена атаки** (`previewItemAttack` → `{ prepAp, shotAp, nextShotAp, totalAp, affordable, apLeft }`): недостающие шаги цепочки (`prepAp`, например «Взять в руки») + первый выстрел (прицеливание + спуск, `firstShotAp`). Всё оценивается с COR: шаги — `_priceSteps`, выстрелы (первый и следующие в очереди) — `shotApCost(actor, baseAp)`; та же функция берёт ОД при выстреле, поэтому кнопка показывает то, что спишется. Темп стрельбы (таймер автоогня, RPM) от COR не зависит — он на глобальном `AP_PER_SECOND`; зависимость от навыка — отдельная карточка. На кнопке «Атаковать» в HUD: слово, под ним `prepAp` (тусклый, если есть) + красный значок прицела с `shotAp`; в подсказке ещё `nextShotAp` для очередей. В бою, если ОД не хватает на `totalAp`, кнопка остаётся нажимаемой, но выглядит недоступной (`is-unaffordable`), подсказка называет «нужно X, есть Y»; нажатие даёт то же предупреждение. **Окна подтверждения нет**: цепочка выполняется сразу, шаги списываются по мере выполнения (диалог `describeChainForConfirm` остаётся за флагом `CONFIRM_ATTACK_CHAIN_ENABLED = false` в `attack-chain.mjs`; так же смена режима/линии без окна). В бою цена **всей** цепочки + первого выстрела проверяется до первого шага (`executeAttackChain({ reserveAp })`): не хватает — не платится ничего. Каждый оплаченный шаг (взять в руки, смена режима/линии, перезарядка, затвор, изготовка) — отдельное действие в логе боя (`logCombatAction`), потому что происходит ДО атаки.
  - **Атака в логе:** выстрелы пишутся не отдельными сообщениями, а в **запись об атаке** (`weapon/attack-log.mjs`): с первого выстрела до выхода из прицеливания (`AimingManager.stopAiming`) — одна «Атака». Запись содержит выстрелы (цена, зона дуги, разброс, пролёты мимо, ид лучей, записи пробития) и попадания по токенам (стены не считаются) с точными параметрами; это чистый JSON. Выход из прицеливания пишет её в чат один раз (`actions/attack-report.mjs`): **в бою** — раскрываемая строка `attack` в журнале действий актёра (+ строка в таблице действий боя с суммой ОД); **вне боя** (и если журнал писать нельзя) — отдельное сообщение. Строка показывает сводку (цель × число попаданий) и **одну кнопку «Пробитие» на выстрел** — она открывает окно выстрела (слои, энергия, факты о каждом попадании и о выстреле: куда, центровость, множитель энергии и качество, часть и урон, дуга, разброс — [[PENETRATION_VIEW]]); у атаки из одного выстрела кнопка в самой строке, у атаки из нескольких шеврон раскрывает список выстрелов с кнопками. Рендер — `actions/attack-journal-html.mjs`, панель открывается только в DOM (`sh-journal-toggle-panel`).
  - **Изготовка** (`weapon.ergonomics.readying`, шаг цепочки `ready`, флаг `weapon.state.ready` на оружии) платится при входе в прицеливание и действует, пока оно не прервано: выстрелы внутри одного прицеливания её не повторяют. Любой выход из прицеливания (`AimingManager.stopAiming`: ESC, ПКМ, «Отмена», кнопка HUD) снимает флаг (`_standDownWeapon`), поэтому следующая атака снова показывает и списывает изготовку. Перезапуск прицеливания тем же оружием (`startAiming` поверх прежнего) её не сбрасывает.
  - **Оружие на время атаки:** если атака запущена не с выбранного оружия (хотбар, лист), оно становится выбранным в быстром HUD (и берётся в руки цепочкой), а когда прицеливание кончится, возвращается прежний выбор, а оружие, которого не было в руках, убирается (`_borrowWeaponForAttack`; выбор — `helpers/hud-selection.mjs`).
- **Меню ПКМ предмета** дополнительно содержит группу «Режим стрельбы» (`switchWeaponMode`: явная смена линии/режима с ценами exit/enter, без прицеливания) и переключатель `system.quickAccess` (оружие не в руках получает карточку в быстром HUD).
- **«Снять» у подключённого предмета:** у магазина / батареи, вставленных в оружие (строка-потомок оружия в инвентаре), в меню ПКМ есть «Снять» (`item.<uuid>.detachFromWeapon`, 0 ОД) — та же операция, что «Снять…» в меню самого оружия (`_runWeaponDetach`); предмет оказывается в руках.
- **Журнал раунда пишет не всякий клиент:** игрок, не являющийся автором сообщения и владельцем анкерного актёра, отдаёт запись ГМу (`journal.appendLine`, `journal.replaceMessage` — см. `GM_ACTIONS.md`).

Избранное: `flags.spaceholder.favoriteActionIds` — `getFavoriteActionIds(actor)` / `toggleFavoriteAction(actor, actionId)` (лист и HUD).

## Movement tracking (боевое движение)

Реализация: `module/helpers/actions/movement-manager.mjs` + `module/helpers/combat/combat-session-manager.mjs`.

Lifecycle:

1. Core Foundry завершает перемещение и заполняет `tokenDocument.movement`.
2. `MovementManager` ловит `updateToken` при `movement.recorded && state === 'completed'`. Стоимость одного перетаскивания: в первую очередь **`movement.passed`** (сегмент только что завершённого пути); иначе `movement.history.recorded`, затем суммарный `movement.history` (часто кумулятивно за цепочку ходов — только запасной вариант). Пересчёта по сетке нет. Если ядро не сообщило ни `cost`, ни `distance` (> 0), запись в таблицу боя **не создаётся**. Координаты для undo — `movement.origin` / `movement.destination`, с запасным `from` из `preUpdateToken`, если `origin` нет.
3. В бою движение автоматически превращается в `move`-событие и попадает в action table участника.
4. Для записи движения можно выставить флаг «Вынужденное движение», тогда её AP cost = 0.
5. Undo строится через action events (`action.undo`) и inverse-данные.

## Интеграция в UI

- **Character sheet**: вывод ОД/скорости, доступных действий и редактора кастомных действий.\n  Файл: `module/sheets/actor-sheet.mjs` + partial `templates/actor/parts/actor-actions.hbs`.
- **Item sheets**: вкладка `Теги` (`system.itemTags`) и условные вкладки; `Actions` с редактором `system.actions[]` при включённом теге «Действия».\n  Файл: `module/sheets/item-sheet.mjs` + `templates/item/item-wearable-sheet.hbs` + partial `templates/item/parts/item-actions.hbs`.

## Публичный API

В `module/spaceholder.mjs` экспортировано в `game.spaceholder`:

- `collectActorActions(actor, ctx?)`
- `executeActorAction(actor, action, ctx?)`
- `runActorAction(actorUuid, actionId)` — выполнить действие по id (макросы хотбара; токен — выбранный токен актёра или первый активный на сцене, `resolveActionToken`; нет токена — предупреждение, прицеливание не начинается). Макрос создаётся перетаскиванием чипа действия на хотбар (`ACTION_DRAG_TYPE`, `createActorActionMacro`): из быстрого HUD, из вкладки «Действия» листа и из блока «Действия с предметом» превью инвентаря. Название макроса — название действия (значок перезарядки в карточке оружия даёт макрос перезарядки, а не атаки: ближайший источник перетаскивания побеждает). «Взять в руки» и «Убрать» — один двусторонний макрос (`itemActionToggle`, пары в `ITEM_TOGGLE_PAIRS`): макрос хранит id `…hold`, называется «Взять / убрать: {предмет}», а `runActorActionById` при отсутствии действия подставляет парное, так что нажатие убирает предмет из рук или берёт его в руки — по текущему состоянию. Старые макросы `…stow` работают так же. Id ищется через `findActorAction`: общий список, затем одношаговые действия оружия (перезарядка, «зарядить N», затвор — `hudQuick`), которых нет в общем списке.
- `runItemAttack(itemUuid, { lineId?, modeId? })` — атака предметом (макросы хотбара «Атака»). Макрос создаётся (`createItemAttackMacro`): перетаскиванием на хотбар карточки оружия в HUD, кнопки «Атаковать», кнопки режима/линии (ярлык закреплён за режимом — `ATTACK_DRAG_TYPE`), либо оружия из инвентаря листа (нативный Item drop, `createItemMacro` в `spaceholder.mjs` для `item.canAttack`).
- `combatSessionManager` (turn/side/action tables/undo; events applied on `Combat` flags)
