# Визуализатор пробития

Две части одной вещи:

- **Окно** — собирает математику **всего выстрела** в одном месте, что бы он ни натворил: слои, которые пришлось преодолеть снаряду (стены, броня, часть тела), рядами сверху вниз; вдоль рядов бежит **поток энергии**, который сужается на каждом слое; справа **превью** — что случилось на слое, на который навели, что известно о попадании и о выстреле. Открывается кнопкой выстрела в чате. Выстрел дробью — одна запись, а не туча попаданий: все снаряды идут от верха параллельными линиями колонки энергии, а ниже по очереди — куда попал каждый. Взрыв — список задетых целей, у каждой свои травмы и своя линия.
- **Карточки над токенами** (оверлей) — пока выстрел проходит слои, над каждым токеном (и стеной) на пути появляется полупрозрачная карточка с рядами этой цели (одна на цель, сколько бы снарядов в неё ни попало), на секунды, и гаснет. Быстрый взгляд; детали — в окне.

```js
game.spaceholder.openPenetrationView('shot_abc123')          // по ид луча выстрела
game.spaceholder.openPenetrationView(id, { messageId })      // сначала искать в этом сообщении чата
game.spaceholder.findPenetrationTrack(id)                    // запись пробития луча или null
game.spaceholder.penetrationOverlay.showShot(track, { broadcast })   // карточки над токенами (track — mergeShot().track)
```

Ид — это `shot.uid` луча (`shot_…`), он же `id` записи следа (`ShotRecord`, [[SHOOTING_SYSTEM]]). Окно — на **выстрел** (одно нажатие спуска): мультивыстрел (дробь) — несколько лучей, но окно одно, в нём все лучи собраны в блоки (см. «Один выстрел — одна запись»); открытие по ид любого луча того же выстрела поднимает то же окно.

## Откуда данные

Резолверы уже писали структурную трассу; для окна её дополнили (все поля добавочные):

| Источник | Что в трассе |
|---|---|
| `resolveDamagePackage` (`damage-resolver.mjs`) | события `penetrate` / `hold` / `bypass` / `conduct` / `self-induce` / `damp` с `thickness` (мм) и `layerKey` (ключ слоя брони `armor:<itemId>:<coverageIdx>:<layerIdx>` — по нему берётся имя предмета); у `bypass` — `energy`. Элемент пакета с целым `tag` метит им свои события и `bodyHits` — так видно, какой снаряд что делал (в раненом попадании дроби `tag` — номер дробины) |
| `resolveBodyTraversal` (`body-traversal-resolver.mjs`) | `gap` — слой, пропущенный из-за щели в покрытии (с `before`: сколько слоёв перед ним); `tissue` — ещё `material`, `shellThickness`, `damage` и `tag` пришедшего снаряда |
| `planWallPasses` (`walls/wall-penetration.mjs`) | событие стены (`events[]`) несёт `trace` — трассу резолвера по этому спану |
| `walkProjectileCollisions` (`hit-luck.mjs`) | у токена, до которого дошёл снаряд, `details.wallsBefore` — события стен между предыдущим токеном (или стрелком) и им |
| `ShotManager#createShot` | `shot.muzzleEnergy` — энергия снаряда у дула (точка отсчёта процентов и ширины потока) |

`AimingManager` собирает из этого **запись пробития** луча (`_collectRay` → `_penetrationTrack` → `assembleRayTrack`): для каждого токена, которого достиг луч, — стены перед ним, затем тело (`applyDamagePackage().trace`); стены, за которыми токена нет, — в конце. Дробины одного залпа, ударившие по одному токену кучно, дают **одну рану** (`_applyWound`): её пакет урона идёт одной параллельной фазой, элементы помечены `tag` по порядку дробин, а у ведущего попадания `lanes` — ид лучей дробин в том же порядке; остальные дробины попадают в рану с пометкой `joined`, своих слоёв у них нет. Взрыв (`details.area`) никогда не склеивается: каждая цель — своё попадание, помеченное `parallel` (взрыв достаёт всех сразу, а не одного за другим). Запись кладётся в `ShotEntry.tracks[]` лога атаки (`weapon/attack-log.mjs`) и уезжает в чат вместе с ним (флаги `attackLog` / `actionJournal`) — **больше нигде не хранится**: очистка чата убирает и записи. Там же ид лучей выстрела (`ShotEntry.ids`) и факты о попаданиях (`impacts`, каждое с `shotId` луча), дуге, разбросе, пролётах мимо.

Где урон ждёт ГМа (`status: 'queued'`), тела в записи нет: группа с пометкой `pending` («Урон ждёт ГМа»), стены перед ней известны.

## Формат записи (`damage/penetration-track.mjs`)

Чистые данные, без Foundry; числа округлены до сотых, тексты обрезаны (читается из флага чужого клиента — `sanitizePenetrationTrack` проверяет всё; картинка — только путь, не `javascript:`/`data:`).

```
PenetrationTrack { v, shotId, projectile, energy, streams?, groups[] }
  energy       — энергия у дула; ширина потока и проценты считаются от неё (нет — от входа в первый слой)
  streams      — только у записи выстрела целиком: ид потоков (путей снарядов) в порядке, в котором их встречают группы
  TrackGroup   { kind: 'wall'|'body', title, subtitle?, img?, hit?, tokenId?, at?, scale?, quality?, pending?,
                 parallel?, lanes?, rays?, streams?, stages[] }
                 title/subtitle: цель и часть тела; img: картинка токена; hit: индекс попадания среди попаданий
                 луча в логе; tokenId / at: токен и точка попадания (у стены — точка входа) — куда вешать
                 карточку; scale/quality: доля энергии, дошедшая до тела; parallel: группа не продолжает
                 предыдущую (взрыв); lanes / rays: группа — рана нескольких снарядов (дробины одного залпа), rays —
                 ид их лучей, а у каждого элемента стадий есть lane — номер снаряда; streams: потоки (индексы в
                 `streams` записи), которые встречают группу, в порядке её линий
    TrackStage { kind: 'wall'|'armor'|'tissue', side?: 'entry'|'exit', verdict: 'pass'|'hold'|'skip', skip?: 'degraded'|'gap',
                 name, material, thickness (мм), source (предмет брони), resist (энергия, которую держит слой),
                 lostBefore (потеряно до слоя), items[], notes? }
      TrackItem { type, verdict, eIn, eOut, dIn, dOut, lane? }   — один тип урона одного снаряда на слое
```

Слой с несколькими типами урона — одна стадия с несколькими `items`; ряд показывает самый энергичный (`primaryItem`), остальные — в превью. Вердикт стадии — вердикт этого элемента: `pass` — снаряд прошёл, `hold` — слой его удержал (`eOut = 0`), `skip` — слой не участвовал (обход из-за износа или щель). Для ткани `pass` — пуля прошла насквозь, `hold` — застряла (`notes.inShell` — остановила оболочка, например череп).

`notes`: `wear`, `integrity`, `conduct` (удар, переданный дальше), `deposit` (урон, который получила ткань), `organs`, `coverage` (щель), `reason` (`opaque` / `unbounded`), `mode`.

`entryRays(entry)` — лучи выстрела (`ids`; у записей без них — из треков и записей следов), `findTrackEntry(logs, shotId)` — выстрел, которому принадлежит луч.

Размер: ~0.5–1.7 КБ на луч. В логе хранится не больше `MAX_TRACKS_PER_LOG` (60) записей, в группе — 24 стадии и `MAX_LANES` (16) снарядов.

## Один выстрел — одна запись (`damage/penetration-shot.mjs`)

Выстрел из нескольких лучей (дробь, взрыв) — несколько записей, по одной на луч; окно же показывает не лучи, а **то, что они встретили**. `mergeShot({ entry })` (чистая функция) сливает записи в один трек того же формата:

- **блок** — стена или часть тела цели («Бандит / Грудь»); две дробины в одно плечо — один блок, одна в плечо и одна в грудь — два. Блоки одной цели в списке стоят вместе (по порядку, в котором цели впервые встречены): окно собирает из них **одну группу — цель** с частями тела внутри;
- **линия (lane)** — один снаряд в блоке: луч, либо дробина общей раны (её элементы в слоях различаются `lane`). Слои блока общие, их сопоставляют по виду (вид, сторона, название, толщина, предмет брони), у каждого слоя — элементы всех снарядов, вердикт слоя — «кто-то прошёл», иначе «кто-то остановлен». Заметки раны (износ, ткань, органы) записаны один раз — не по числу дробин;
- **поток (stream)** — путь снаряда через весь выстрел: луч, а у взрыва — доля взрыва, достающаяся цели (каждая цель-часть — свой поток: `<луч>#<n>`). Потоки нумеруются в порядке, в котором список блоков их встречает (`track.streams`; `groups[i].streams` — потоки, встречающие блок `i`, в порядке его линий): первый поток — тот, чьи записи идут первыми. Нумерация идёт по блокам, поэтому линии общего блока и линии одной цели стоят рядом. Запись выстрела сама говорит о потоках (поэтому у другого клиента та же раскладка); запись одного луча без `streams` читается так: луч — один поток, дробины раны (`rays`) — по потоку на каждую, группа взрыва (`parallel`) — поток своей;
- **`parallel`** у блока с несколькими линиями — всегда (линии одного блока не несут энергию друг в друга);
- **попадания** блока (`impacts[i]` рядом с треком) — попадание ведущей дробины и попадания присоединившихся (`joined`), чтобы окно собрало факты по блоку;
- **пустой блок** (`bare`) — попадание без слоёв (урон не применён, цель без брони и тела) тоже строка списка; санитайзер чужого клиента такие группы выкидывает — карточкам и сокету они не нужны.

Выстрел из одного луча даёт запись этого луча. Лучи в сокет не рассылаются: `AimingManager._showPenetration` сливает записи в руках (`mergeShot({ rays, impacts })`) и шлёт одну запись выстрела.

| `src/scss/components/_penetration-view.scss` | стили окна и карточек |

**Ряд** — все ряды одной высоты (слой 36 px, шапка группы 42 px; толщина слоя — числом, не высотой). **Предмет:** слои одной вещи (бронежилет, одежда; `stage.source` — имя предмета у актёра), идущие подряд в части тела, образуют «серию»: над первым слоем серии — строка с названием предмета (`__piece`, ряд выше на 16 px, в карточке на 13; это отдельная строка сетки ряда, а не `padding-top`: колонка энергии растянута на обе строки, иначе в потоке над слоем была бы дыра), вдоль всех её слоёв — боковая скобка `[` (`::before` ряда, загнутые концы на первом и последнем слое; щель в покрытии этого предмета внутри серии тоже под скобкой). Слои без предмета (ткань, стена, природная «кожа») — без скобки. Текст рядов серии стоит там, где у самого широкого её ряда (`--mr` = `pieceUsed` модели), чтобы скобка была прямой, а «ступенька» влево от закончившихся линий — между сериями. Слева кромка цвета вида слоя (стена / броня / ткань), название и толщина в мм, справа вердикт (оранжевый — снаряд прошёл, зелёный — слой удержал, серый — не участвовал). **Группа — цель** (или стена): шапка и под ней по частям тела. Шапка: картинка токена (нет или не загрузилась — иконка), имя с значком «×6» (сколько снарядов попало в цель), под именем — **вторая строка**: части тела, в которые попало («Левая ступня, Голова»), у цели с одной частью — ещё метка «скользящее ×0.6» / «×0.99» (если до тела дошла не вся энергия), у свёрнутой — ещё краткая сводка (урон, или «ждёт ГМа»); справа кнопка «свернуть» (шеврон). Цель с несколькими частями: каждая — **строка части** (название, значок «×N», под названием своя метка «скользящее ×0.84») и под ней её слои; у цели с одной частью строки части нет — слои идут сразу под шапкой. Имя и вторая строка не делят одну строку (раньше часть и сводка вытесняли имя): режутся многоточием только по ширине всей строки, а стопка рядов шире, чем больше линий (`max(440px, колонка энергии + 300px)`). На карточке над токеном метка — только число («×0.69»), слово («скользящее») осталось в окне (в модели метка разобрана на `chip`, `chipQuality`, `chipScale`).

**Колонка энергии** — левая колонка рядов (`parts/penetration-flow.hbs`), две части:
- **Числа** — одна вертикальная колонка X → Y → Z, каждое число стоит на границе между рядами: что выходит из каждого слоя (у удержавшего — 0) и что входит в первый слой цели — последнее только если это не то, что отпустил предыдущий слой (потеря на дистанции, скользящий удар), иначе значение не повторяется. У слоёв, не участвовавших в проходе (щель, обход), чисел нет. Проценты и остальное — в превью.
- **Поток** — контур, ширина вверху ряда — энергия на входе, внизу — на выходе (100% = энергия у дула = 80% колонки); SVG с `preserveAspectRatio="none"` и неизменной толщиной линии. Слой, удержавший снаряд, сводит поток в точку; шапка группы продолжает поток от того, что отпустил предыдущий слой, до того, что входит в первый слой цели. **Поток без разрывов**: у рядов нет ни границ, ни полей (базовый CSS Foundry даёт `ol li` отступ 0.25rem — у ряда он обнулён; разделители рядов и групп нарисованы только рядом с колонкой энергии, `::after` ряда и `::before` шапки группы), куски потока соседних рядов перекрываются на полпикселя, слой, не участвовавший в проходе (щель, обход), пропускает поток как есть. Нарисован бледно и полупрозрачно: пунктир — маршрут, оранжевый контур с лёгкой заливкой дорисовывается, когда до ряда доходит снаряд, — чтобы «огонёк» снаряда оставался самым ярким. Числа появляются вместе с потоком.

**Линии.** Колонка потока режется на столько ячеек, сколько потоков у выстрела (до 16, `MAX_LANES`; ширина колонки растёт с числом линий: `streamWidth`, 64 px для 1–4, до 160 px), и у каждого снаряда своя линия **на весь список**: все стартуют сверху с энергией у дула и идут бок о бок. Цели выстроены справа налево: сверху — записи самой правой линии (поток №1), затем следующей слева и так далее; общий блок (стена, через которую прошли две дробины, часть тела с двумя попаданиями) стоит там, где его впервые встретил самый правый из его потоков, и в нём линии стоят рядом. Линии одной цели **спускаются к разным частям тела**: шапка цели пропускает их все (прямо вниз), строка части сужает свои линии, остальные идут дальше к своим частям. **Ряды сдвигаются влево на место закончившихся линий:** линии кончаются справа, поэтому каждая строка берёт у колонки только нужные ей линии (`used` модели, `--m` строки: ширина колонки строки — доля `--m` из `--lanes`), а её текст начинается левее — список читается как лесенка, пустого места справа от закончившихся линий не остаётся. Линии в строке нарисованы в колонке именно этой ширины (контур считается на `used` ячеек, линия остаётся на месте), поэтому она идёт ровно вниз из строки в строку. В строке, которой линия не касается, она идёт прямо вниз как есть; линия, чьи записи закончились (последний слой, где она прошла, или слой, остановивший её), дальше не рисуется — список читается как дерево, где линии одна за другой «отваливаются» от колонки. Линия, которая прошла стену и пошла к телу, продолжается там, где её оставила стена (или с потерей между ними — тогда число входа дописано). Потоков больше 16 — лишние линии не получают, их блоки в списке остаются. Числа колонки — **суммы** по снарядам этого блока (сколько энергии несёт залп); слой, на котором часть снарядов остановлена, подписан «5 из 6» (если все прошли или все остановлены — обычный вердикт), в превью слоя — строка на каждый снаряд («Снаряд 3: 30 (75%) → 20 (50%)»), урон всех вместе по типам, сопротивление слоя, износ. Карточка над токеном рисует линии только своей цели (раскладка та же, но потоки пронумерованы заново по цели).

**Сворачивание.** Всё развёрнуто, сколько бы целей ни было. Шеврон в шапке цели сворачивает её до одной строки (имя; вторая строка — части и краткая сводка: урон, или «ждёт ГМа»), кнопка в шапке окна — все цели (если все свёрнуты — раскрывает). Линии при этом остаются: у шапки свёрнутой цели свои контуры (линии сужаются до того, что выходит из цели), у развёрнутой — до первой строки части. Когда свёрнуты все цели, чисел в колонке нет и место под них (`--num-w`) сжимается — отступа слева не остаётся. Анимация идёт только по тому, что на экране (комета свёрнутой цели останавливается на шапке).

**Анимация** (Web Animations API): пока не дошёл снаряд, ряды тусклые, а поток — только бледный «маршрут». Все «кометы» (по одной в ячейке каждой линии) стоят сверху, бок о бок, а дальше идут **строго по одной, справа налево**: пока летит одна, остальные ждут наверху, а когда она закончила (её остановил слой или она вылетела из последней строки), стартует следующая слева. Строки выстроены в том же порядке, поэтому список читается один раз сверху вниз и в каждый момент анимируется одно место. Комета падает вниз по своей линии (длинный путь — быстро, прыжок к соседней строке — медленнее) и останавливается только у своих строк — у шапки цели, которую она встречает, и у слоёв, через которые идёт (мимо чужих летит, не задерживаясь). Слой, в котором не участвовал ни один снаряд (щель, обход без записей), «своим» считают линии блока, которые до него ещё живы: комета заходит и на него, а ряд загорается в свой черёд, а не в самом конце. Если ряд ниже слоя, остановившего снаряд (до него никто уже не дошёл), то он показывается сразу вслед за остановкой — как результат «не достигнуто / обход». На каждом своём ряду поток заливается яркой частью сверху вниз, ряд подсвечивается, комета сужается вместе с энергией. Чем больше комет, тем короче каждая задерживается на слое. Слой, удержавший снаряд, останавливает именно его: комета гаснет на месте (не двигаясь) и в самом низу потока, в ячейке этого снаряда, остаётся короткая красная горизонтальная чёрточка (`__stopmark`), острый конец потока упирается в неё — пуля остановлена; от правого края чёрточки к левому краю названия строки, остановившей снаряд (вертикальный центр строки), идёт тонкая красная линия (`__stopline`) — видно, какой слой остановил какую линию. В свёрнутой цели комета останавливается на шапке (чёрточка — под ней, линия — к шапке, если в цели кого-то удержали). Без анимации (пропуск, `prefers-reduced-motion`) чёрточки стоят на удержавших слоях сразу. Те, чьи записи кончились и кого не удержал никто, вылетают вниз из своей последней строки и пропадают. Превью и прокрутка окна идут за летящей кометой. Строки несут разметку для анимации: `data-here` (какие линии эта строка касается), `data-stops` (какие удержаны слоем; у шапки свёрнутого блока — `data-stops-folded`: удержанные где-либо в блоке), `data-widths` (энергия каждой линии после ряда). Кнопка в шапке — «Повторить», во время анимации — «Пропустить». `prefers-reduced-motion` — сразу итог. Без JS (или после пропуска) виден итог: состояние «ещё не достигнуто» включается только классом `is-animating`.

**Превью** (справа): заголовок (что случилось: «9x19 пробивает Кевлар 1 мм, энергия 46 (92%) → 6 (12%)» / «Кевлар 3 мм останавливает 9x19, энергия 30 (60%) → 0»), предмет брони и таблица: энергия «вход → выход» (проценты от энергии у дула), сопротивление слоя, «не хватило энергии» (у удержавшего слоя), урон по типам «до → после», остальные типы, потеря до слоя, износ, переданный удар, урон ткани, органы. Показывает: слой/цель под курсором (клик закрепляет, повторный клик снимает), пока идёт анимация — тот, у которого снаряд (курсор не мешает), по окончании — слой, остановивший снаряд (или последний из раскрытых блоков). Шапка цели в превью — крупная картинка и **факты о попадании** (`shot-info.mjs`). Внизу всегда **факты о выстреле** и пролёты мимо.

**Выстрел без слоёв**: ничего не встретивший показывает «Снаряд ничего не встретил» и факты выстрела; попадания без слоёв (урон не применён) всё равно строки списка с фактами. Переключателя лучей нет: окно одно на выстрел.

## Карточки над токенами (`damage/penetration-overlay.mjs`)

Стрелок показывает их, когда урон посчитан (`AimingManager._showPenetration` → `penetrationOverlay.showShot`), и рассылает запись выстрела остальным клиентам по сокету `system.spaceholder` (`spaceholder.penetrationOverlay`, вместе с `sceneId`; при включённом «auto render» — как и следы). Клиент проверяет сцену и `sanitizePenetrationTrack`. **Карточка на цель** (`cardTracks`: запись выстрела режется на записи-карточки — блоки одного токена, то есть части тела, в которые попало, вместе, стены — по месту; потоки в каждой пронумерованы заново, так что линии карточки — это снаряды цели, спускающиеся к её частям), по очереди в порядке полёта (380 мс между ними — снаряд в пути; цели взрыва — 140 мс, их достаёт «сразу»); все блоки карточки раскрыты; та же анимация почти вдвое быстрее; висит 4.5 с и гаснет 0.7 с. Привязка: к токену (`canvas.tokens.get(tokenId).bounds`), иначе к точке попадания; над токеном, иначе под, справа, слева — `placeCard` не даёт карточкам перекрыться и не выпускает их за экран; на `canvasPan` карточки идут за токенами. Новая карточка на тот же токен заменяет старую (дробь по одному токену — одна карточка, а не по числу дробин). Группа, которой негде висеть, карточки не получает.

Настройка клиента «Пробитие поверх токенов» (`penetrationOverlay`, по умолчанию вкл).

## Журнал чата

В записи атаки (`actions/attack-journal-html.mjs`) — только сводка: цели и число попаданий. **Одна кнопка на выстрел** («Пробитие»): атака из одного выстрела — кнопка прямо в строке; из нескольких — шеврон раскрывает список выстрелов (название, попадания, ОД), у каждого своя кнопка. Построчного дампа попаданий и диагностики выстрела в журнале больше нет — они в окне. Клик ловит делегированный обработчик журнала (`action-chat-journal.mjs`, `data-action="sh-journal-open-penetration"`) → `game.spaceholder.openPenetrationView(shotId, { messageId })`.

## Ограничения

- Запись есть только у выстрелов после появления функции (старые сообщения кнопок не получают, у записей без `ids` ид берётся из трека).
- Стены, которые снаряд прошёл, но за которыми нет токена, и стены, остановившие снаряд, идут в конце записи. У выстрела из нескольких сегментов (рикошет) стена первого сегмента, за которой токен только на втором, окажется после этого токена.
- Слои, до которых снаряд не дошёл (за удержавшим), в записи нет — резолвер их не трогает.
- Колонка держит до 16 линий (`MAX_LANES`), блок — до 16 снарядов: дробин в одной ране больше — лишние делят последнюю линию (в пакете их `tag` = 15), потоков больше 16 (много отдельных лучей, цели-части взрыва) — лишние остаются без линии, а блоки — в списке.
- Линия начинается с энергии у дула; энергия, которую она несёт из блока в блок, — то, что вышло из последнего слоя предыдущего блока этого потока (потеря между ними — шапка следующего блока). Числа колонки — суммы по снарядам этого блока.
- Органы — строка в превью ткани, а не отдельные ряды: они бросок по месту попадания и энергию снаряда не забирают.
- Карточки приходят остальным клиентам, только пока идёт прицеливание с «auto render»; позже — окно из чата.
