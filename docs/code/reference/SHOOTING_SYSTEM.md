# Система стрельбы и выстрелов SpaceHolder

Документация актуальной архитектуры системы выстрелов (2025).

## Обзор

Выстрел строится из трёх стадий:

1. **Payload** — JSON-описание траектории (сегменты, коллизии, поведение при попадании)
2. **ShotManager** — расчёт траектории и попаданий (`payload` → `shotResult`)
3. **DrawManager** — визуализация `shotResult` на canvas

### Модули (актуальные)

| Модуль | Путь | Назначение |
|--------|------|------------|
| **AimingManager** | `helpers/aiming-manager.mjs` | UI прицеливания, выбор payload, вызов ShotManager |
| **ShotManager** | `helpers/shot-manager.mjs` | Расчёт траекторий, коллизий, рикошетов, пробития |
| **DrawManager** | `helpers/draw-manager.mjs` | Отрисовка линий, кругов, конусов, маркеров попаданий; следы затухают по возрасту |
| **shot-trail** | `helpers/shot-trail.mjs` | Запись выстрела (`ShotRecord`: чистый JSON для чата и отрисовки), кривая затухания, настройка времени жизни |

Payloads хранятся в `module/data/payloads/*.json`.

### Устаревшие модули (legacy)

- **AimingSystem**, **RayCaster**, **RayRenderer** — в `helpers/legacy/`, не используются
- См. `legacy/AIMING_SYSTEM_DOCUMENTATION.md` только для справки по старой архитектуре

## Структура Payload

```json
{
  "id": "unique_id",
  "name": "Название",
  "description": "Описание",
  "type": "linear|area|complex|melee",
  "trajectory": {
    "segments": [ /* массив сегментов */ ]
  }
}
```

Поле `type` — метаданные для UI; логика выстрела определяется только `trajectory.segments`.

## Типы сегментов и их настройки

### 1. `line` — прямая линия

Простой отрезок от текущей позиции в заданном направлении.

| Параметр | Тип | Описание | Влияние на траекторию |
|----------|-----|----------|------------------------|
| `direction` | number | Угол относительно текущего направления (град.) | Направление отрезка |
| `length` | number | Длина в единицах `defSize` (grid.size/grid.distance) | Длина до проверки коллизий |
| `collision` | object | См. ниже | Что проверять при столкновении |
| `onHit` | string | `"stop"`, `"next"`, `"need"` | Поведение при попадании |

**Поведение `onHit`:**

- `stop` — добавить первое попадание, завершить траекторию (конец сегмента = точка попадания)
- `next` — проникновение: добавить все попадания **по порядку полёта до первой стены, которая остановила снаряд, включительно** (за ней ничего не задевается), продолжить к следующему сегменту. Стены с материалом снаряд может пробить — см. [[WALL_PENETRATION]]; стена без материала по-прежнему останавливает
- `need` — нужно попадание: записывается **только первое касание** (токен или стена), выстрел продолжается от него (ракета взрывается на цели); если попадания не было — завершить выстрел. Если касание пришлось на **стену**, точка конца сегмента (она же центр следующего круга) сдвигается от стены назад к стрелку на `WALL_BLAST_STANDOFF_PX` (2 px, `backOffFromWall`): стена — бесконечно тонкая линия, и взрыв ровно на ней сам себя «закрывает» стеной, так что токены на открытой стороне не получали бы сплэша. Метка попадания остаётся на самой стене.

Длина простой линии без лимита (`simpleLimit.enabled = false`) — ширина + высота холста (с отступами) **в пикселях**, переведённая в единицы измерения (`resolveDefaultSceneSegmentLength`); раньше из-за пропущенного деления на размер клетки она получалась в ~100 раз длиннее.

### 2. `circle` — круг (AOE, взрыв)

Круг с центром в текущей позиции. Не двигает позицию — `endPos` остаётся `lastPos`.

| Параметр | Тип | Описание | Влияние |
|----------|-----|----------|---------|
| `range` | number | Радиус в единицах `defSize` | Размер зоны |
| `coverageMode` | string | `"proportional"` (по умолчанию), `"any"`, `"center"`, `"full"` | Кого и насколько задевает зона — см. «Покрытие АоЕ» |
| `lineOfSight` | boolean | `true` (по умолчанию) / `false` | Учитывать ли укрытия (стены и токены) при расчёте покрытия |
| `excludeDirectHit` | boolean | `false` (по умолчанию) / `true` | Не задевать токены, в которые снаряд уже попал прямо (линия/свинг) |
| `ignoreDirectHitCover` | boolean | `false` (по умолчанию) / `true` | Токены, в которые снаряд уже попал прямо, не прикрывают других от зоны |
| `coverageForFullEffect` | number | `1…100` %, по умолчанию `100` | Покрытие, при котором `proportional` даёт полный эффект (50 → покрытие 25% = половина) |
| `collision` | object | См. ниже | Стены/токены |
| `onHit` | string | По умолчанию `"next"` | stop/next/need |
| `hitOrder` | string | `"near"`, `"far"`, `"left"`, `"right"` | Порядок выбора целей |
| `hitAmount` | number | Лимит попаданий (undefined = все) | Сколько целей считать |

### 3. `cone` — конус

| Параметр | Тип | Описание | Влияние |
|----------|-----|----------|---------|
| `direction` | number | Угол относительно текущего направления (град.) | Ось конуса |
| `range` | number | Внешний радиус | Размер зоны |
| `angle` | number | Угол раскрытия в градусах (по умолчанию 90) | Ширина конуса |
| `cut` | number | Внутренний радиус (0 = конус от центра) | Усечённый конус |
| `coverageMode` | string | `"proportional"` (по умолчанию), `"any"`, `"center"`, `"full"` | См. «Покрытие АоЕ» |
| `lineOfSight` | boolean | `true` (по умолчанию) / `false` | См. «Покрытие АоЕ» |
| `excludeDirectHit` | boolean | `false` (по умолчанию) / `true` | См. «Покрытие АоЕ» |
| `ignoreDirectHitCover` | boolean | `false` (по умолчанию) / `true` | См. «Покрытие АоЕ» |
| `coverageForFullEffect` | number | `1…100` %, по умолчанию `100` | См. «Покрытие АоЕ» |
| `collision` | object | См. ниже | Стены/токены |
| `onHit` | string | По умолчанию `"next"` | stop/next/need |
| `hitOrder` | string | `"near"`, `"far"`, `"left"`, `"right"` | Порядок целей |
| `hitAmount` | number | Лимит попаданий | Сколько целей |

### 4. `swingFan` (старое имя `swing`, алиас `legacySwing`) — серия конусов

Последовательность конусов с меняющимися параметрами. Для ближнего боя используйте новый `swing` (раздел 4a).

| Параметр | Тип | Описание | Влияние |
|----------|-----|----------|---------|
| `direction` | number | Начальный угол | Ось первого конуса |
| `range` | number | Начальная дальность | Размер первого конуса |
| `angle` | number | Угол каждого конуса | Ширина |
| `cut` | number | Отсечение каждого конуса | Внутренний радиус |
| `coverageMode` | string | Передаётся в каждый конус | См. «Покрытие АоЕ» |
| `lineOfSight` | boolean | Передаётся в каждый конус | См. «Покрытие АоЕ» |
| `excludeDirectHit` | boolean | Передаётся в каждый конус | См. «Покрытие АоЕ» |
| `ignoreDirectHitCover` | boolean | Передаётся в каждый конус | См. «Покрытие АоЕ» |
| `coverageForFullEffect` | number | Передаётся в каждый конус | См. «Покрытие АоЕ» |
| `directionStep` | number | Приращение угла на конус (град.) | Поворот серии |
| `rangeStep` | number | Приращение дальности на конус | Расширение/сужение |
| `count` | number | Количество конусов | Длина серии |
| `collision` | object | См. ниже | Стены/токены |
| `onHit` | string | `"stop"`, `"next"`, `"skip"`, `"need"` | Поведение |
| `hitOrder` | string | Передаётся в каждый конус | Порядок целей |
| `hitAmount` | number | Передаётся в каждый конус | Лимит целей |

**Поведение `onHit` для swingFan:**

- `stop` — при попадании в любом конусе — завершить весь выстрел
- `skip` — при попадании — пропустить оставшиеся конусы и перейти к следующему сегменту payload
- `next` / `need` — как для конуса

### 4a. `swing` — размах кромки (ближний бой)

Конус с вращающейся кромкой от точки удара. **Размах останавливается о первую стену или токен, которых коснулась кромка** (меч задел стену или врага). Точный угол касания уточняется бисекцией, поэтому результат не зависит от грубости выборки. Как касание превращается в попадание, решает `hitMode`:

| `hitMode` | Кого задевает | Центровость / покрытие |
|------------|---------------|------------------------|
| `simple` | первый токен на пути | центровости нет (полное попадание без крита), покрытие не используется |
| `side` (по умолчанию) | первый токен на пути | центровость — по линии, проведённой **через точку касания перпендикулярно кромке** (направление удара): прямой удар, который «чуть задел», читается как точный; касание на пределе дальности или хордой — хуже |
| `area` | все в зоне | размах останавливается, но покрытие считается так, будто нет: обычная конусная АоЕ по всей зоне (`coverageMode`, `lineOfSight`, `coverageForFullEffect`, `excludeDirectHit`, `ignoreDirectHitCover`, `hitOrder`, `hitAmount`); центровости нет |
| `deep` | первый токен на пути | токен запоминается, размах продолжается до **другой** стены/токена (или конца дуги); центровость — по положению кромки, ближайшему к центру токена |

Параметры: `direction`, `range`, `cut`, `angle`, `side`, `hitMode`, `collision`, `onHit` (`stop` — выстрел заканчивается, если удар пришёлся во что-то; `need` — продолжается только после попадания).

**Сторона размаха (`side`).** `right` — удар слева направо (с точки зрения бойца), `left` — справа налево. Значение `auto` (по умолчанию, у встроенных ближних payload) выбирает сторону по прицелу: размах идёт **к центру дуг прицеливания** (направлению взгляда токена). Прицел левее взгляда — слева направо, правее — справа налево; ровно по центру (в пределах `SWING_CENTER_DEAD_ZONE_DEG`, 0.5°) — случайно. Фиксированные `left` / `right` в payload побеждают (`resolveSwingSide`, `weapon/trajectory.mjs`). Выбранная сторона записывается в `shotPaths[].side` — по ней рисуется кромка.

**Стены и размах.** Кромка — луч от `cut` до `range`; размах останавливается на первом угле, где луч что-то коснулся. Стена закрывает цель, только если пересекает луч **на этом же угле раньше цели** (ближе к бойцу). Короткая стена, которую цель «выглядывает» из-за края, не закроет цель: клинок проходит мимо её края и задевает цель сбоку. Чтобы цель была закрыта целиком, стена должна перекрывать её угловую ширину.

- Касание **стены** заканчивает размах без урона (в `area` покрытие всё равно считается, стены работают через LoS).
- `simple` / `side` / `deep` попадают по одному токену; несколько целей — только `area`.
- Качество попадания (`hit-quality.mjs`, ниже) считается по центровости из таблицы выше. В `area` качества нет, как у любой АоЕ.
- В `shotPaths` путь `swing` несёт `edgeDeg` — угол, на котором кромка остановилась (его рисует `DrawManager`).
- Тест чистой геометрии: `node module/helpers/weapon/swing.test.mjs`.

### 5. `complexLine` — линия с рикошетами

Серия отрезков с рикошетом от стен/токенов. Токен, от которого луч не отрикошетил, всегда его останавливает: пробития по характеристикам персонажа нет (раньше `penetration` сравнивалось с END цели; пробитие будет решать пайплайн урона).

| Параметр | Тип | Описание | Влияние |
|----------|-----|----------|---------|
| `direction` | number | Начальное направление (град.) | Ось первого отрезка |
| `length` | number | Длина одного отрезка | Шаг траектории |
| `amount` | number | Количество отрезков | Макс. длина траектории |
| `collision` | object | См. ниже | Стены/токены |
| `damage` | object | `{ ricochet }` | Логика рикошета |
| `onHit` | string | По умолчанию `"stop"` | stop/next/skip |

**`damage`:**

- `ricochet` — максимальный угол (град.) для рикошета от стены/токена; при большем угле — остановка

## Покрытие АоЕ (`coverageMode`)

У `circle` / `cone` / `swingFan` (и `swing` в режиме `area`) нет ни удачности выстрела, ни центровости — у зоны есть только **coverage** (0–1, доля сэмплов токена внутри зоны и не закрытых стенами/токенами). Сегмент сам решает, как покрытие превращается в эффект:

| `coverageMode` | Условие попадания | Эффект |
|----------------|-------------------|--------|
| `proportional` (по умолчанию) | `coverage > 0` | пропорционально покрытию (`effectScale = coverage`) |
| `any` | `coverage > 0` | полный (`effectScale = 1`) |
| `center` | центр токена в зоне и не закрыт | полный |
| `full` | `coverage == 1` (100%) | полный; иначе токен не задет |

**Покрытие для полного эффекта (`coverageForFullEffect`).** Только для `proportional`: процент покрытия, при котором эффект уже полный. Ниже него эффект растёт линейно: `effectScale = min(1, coverage / coverageForFullEffect)`. При 50% покрытие 25% даёт ×0.5, покрытие 50% и выше — ×1. По умолчанию `100` (эффект равен покрытию, как раньше). Для остальных режимов опции нет смысла: их эффект и так полный.

Токен, не прошедший условие, **не попадает в `actualHits`**, поэтому `hitOrder` / `hitAmount` / `onHit: "need"` считают только реально задетых.

Детали попадания (`hit.details`): `area: true`, `coverage`, `coverageMode`, `effectScale`, `centerCovered`, `clock` (сторона к центру зоны — для лицевой/спинной брони), `hitPoints`.

Применение урона (`AimingManager._resolveHitImpacts`): без качества — случайная группа/часть. При `effectScale < 1` урон (`damage`) масштабируется через `ShotManager.buildScaledApplications`; бронепробитие не масштабируется.

**Линия обзора (`lineOfSight`).** По умолчанию `true`: покрытие считается с учётом стен и токенов-укрытий (от взрыва можно спрятаться за стеной или за другим токеном). При `false` сэмплы токена не проверяются на LoS вовсе — зона достаёт сквозь укрытия (заклинание). Опция действует и на режим `center` (центр «не закрыт»). Фильтр `collision.tokens` (свои/чужие) от неё не зависит.

**Прямая цель (`excludeDirectHit`).** По умолчанию `false`: токен, в который попал снаряд, остаётся в зоне и получает АоЕ вдобавок к прямому попаданию (ракета). При `true` АоЕ пропускает все токены, которых этот выстрел уже коснулся напрямую (линия, свинг; попадания самих АоЕ не считаются) — для эффектов вроде «цель замораживается, всем вокруг замедление». Исключённый токен только не получает эффект: как укрытие для LoS он продолжает работать.

**Прикрытие токенов.** Токен прикрывает других от АоЕ не всем своим хитбоксом, а кругом меньшего радиуса: `TOKEN_COVER_RADIUS_FACTOR` (0.5) × меньший из радиусов «тело» и «хитбокс-мишень» (`ShotManager._targetCoverRadius`). Поэтому взрыв на поверхности цели начинается *снаружи* её прикрытия: соседи получают хотя бы часть покрытия, а за целью остаётся «тень» шириной ±30° (при 0.5; `sin θ = factor`). Увеличенный хитбокс прикрытие не раздувает; уменьшенный (уклонение) уменьшает и прикрытие, чтобы оно всегда оставалось меньше мишени.

**Прикрытие прямой цели (`ignoreDirectHitCover`).** По умолчанию `false`: токен, в который попал снаряд, продолжает прикрывать других в пределах своего (уменьшенного) прикрытия. При `true` такие токены вообще не прикрывают от этой зоны (заклинание, которое «обходит» цель). Опция независима от `excludeDirectHit`: цель может получать эффект и не прикрывать, и наоборот. Радиусы целей собраны в `_targetHitRadius` / `_targetCoverRadius` — там же будут правила размера цели в разных условиях (уклонение).

Splash после попадания (`ammo.onHitSplash`) принимает поля `coverage`, `lineOfSight`, `excludeDirectHit`, `ignoreDirectHitCover` и `coverageForFullEffect` — это `coverageMode`, `lineOfSight`, `excludeDirectHit`, `ignoreDirectHitCover` и `coverageForFullEffect` добавляемого круга (по умолчанию `proportional`, `true`, `false`, `false`, `100`).

Проверка в Node: `node module/helpers/weapon/area-coverage.test.mjs`.

## Настройки collision

```json
"collision": {
  "walls": true,   // проверять стены
  "tokens": true   // или объект (см. ниже)
}
```

**Простой вариант:** `"tokens": true` — все токены; `"tokens": false` — игнорировать токены.

**Расширенный вариант (фильтр по диспозиции):**

```json
"tokens": {
  "owner": false,  // игнорировать свой токен
  "ally": true,    // учитывать союзников (та же диспозиция)
  "other": true    // учитывать врагов (другая диспозиция)
}
```

## Цепочка сегментов

Сегменты обрабатываются последовательно. Для каждого сегмента:

- `lastPos` — конечная точка предыдущего сегмента (или центр токена для первого)
- `direction` — направление на выходе предыдущего сегмента (для line/cone — `direction + segment.direction`; для complexLine — после рикошета)

Если `shouldContinue === false` (из‑за `onHit`), следующие сегменты не обрабатываются.

## Результат: shotResult

`ShotManager.createShot()` возвращает UID. Результат получается через `shotManager.getShotResult(uid)`:

```javascript
{
  shotPaths: [
    { type: 'line', start: {x,y}, end: {x,y} },
    { type: 'circle', start: {x,y}, range: number },
    { type: 'cone', start: {x,y}, range, angle, direction, cut }
  ],
  shotHits: [
    { point: {x,y}, type: 'token'|'wall', object, ...details }
  ]
}
```

`shotPaths` и остальное рисуются не напрямую: в конце `createShot` из выстрела строится **запись** (`shot.record`, `shotManager.getShotRecord(uid)`) — чистый JSON без ссылок на токены и стены. Её рисует `DrawManager.drawRecord(record)`: сразу у стрелка, у остальных клиентов — по сокету (`DrawManager.broadcastRecord`, `AimingManager._broadcastShot`), а после перезагрузки и смены сцены — из записей об атаке в чате (`flags.spaceholder.attackLog` и строки `attack` журнала действий; `readShotRecords`). След затухает по возрасту выстрела и не зависит от прицеливания. Формат записи и жизненный цикл — `draw-manager.md`.

`uid` выстрела — `shot_<randomID>` (уникален между клиентами). `ShotSystem` держит в памяти не более 32 последних выстрелов целиком.

## Запись об атаке (чат)

Отладочного сообщения на каждый выстрел больше нет. `AimingManager` ведёт **запись об атаке** (`weapon/attack-log.mjs`, `_attackSession`): первый выстрел сеанса прицеливания открывает её, каждый выстрел (одно нажатие спуска; веер multishot — лучи одного выстрела) добавляет `ShotEntry` — цену ОД, зону дуги, разброс, пролёты мимо, строки по стенам, попадания (`Impact`: токен, центровость, множитель энергии и качество, для АоЕ — покрытие; часть тела и урон, когда он применён) и следы лучей. Выстрелы, ещё летящие в момент выхода из прицеливания, дописываются до отчёта (`inFlight`). `stopAiming` закрывает запись → `reportAttack` (`actions/attack-report.mjs`): в бою — строка журнала действий + строка таблицы боя, иначе отдельное сообщение. Подробности отображения — `ACTIONS_SYSTEM.md`.

Выстрелы платят ОД с COR (`shotApCost`); в бою выстрел, на который ОД не хватает, не происходит (серия обрывается, боеприпас не тратится).

## Урон по чужим токенам

`AimingManager._applyDamage`: владелец цели (в том числе ГМ) вызывает `applyDamagePackage` напрямую; остальные — через `game.spaceholder.gmActions.request('damage.apply', …)`. ГМ в сети применяет урон сразу; если ГМа нет, действие встаёт в очередь, а в чате появляется отдельная заметка «Действие ожидает ГМа» с подписью «кто → кого (часть)» (после применения она исчезает, при отмене — «Отменено ГМом»). Сообщения выстрела, к которому её можно было бы прикрепить, больше нет: запись об атаке пишется только при выходе из прицеливания. Подробности — `GM_ACTIONS.md`.

В записи об атаке урон по чужому токену виден, только если ГМ применил его сразу (`damage.apply` возвращает `bodyDamage`); отложенный урон помечен «ждёт ГМа».

## Качество попадания (`hit-quality.mjs`)

Качество попадания — это **центровость** (`1 − расстояние до центра хитбокса / радиус хитбокса`, `ShotManager._isHitLine`) и ничего больше. Зона дуги прицеливания сюда не входит: она задаёт уверенность выстрела (см. «Уверенность и сопротивление» ниже) и на урон не влияет — решает только, достигнет ли снаряд токена.

От центра токена наружу (зоны — доли ширины хитбокса; три мировые настройки, `registerHitQualitySettings`):

| Зона | Настройка (по умолчанию) | Энергия снаряда | Эффект |
|------|--------------------------|-----------------|--------|
| «Яблочко» | `hitCritZone` (10%) | ×1 | **крит**: эффект крита режима огня |
| Полное попадание | `hitFullZone` (30%) | ×1 | — |
| Скользящее | от края полной зоны до края хитбокса | равномерно падает от ×1 до `hitEdgeEnergy` (10%) на самом краю | — |

Падение линейное, без поясов и порогов: малая разница на границе зоны не превращается в «пробил / не пробил».

**Множитель применяется к энергии снаряда, а не к урону.** `applyEnergyScaleToApplications` (`weapon/damage-profile.mjs`) умножает `energy` каждой записи пакета (у снаряда, прошедшего стены, — остаток энергии после стен), а урон выводится из энергии тем же законом, что и у брони: `damageRatioForEnergyRatio` (`damage/damage-resolver.mjs`; «Снижение урона бронёй» снаряда, 100% — урон пропорционален энергии). Так скользящее попадание имитирует косую плиту (броня поглощает ту же энергию из меньшего остатка и пробивается хуже) и при этом работает без брони: цель просто получает меньше урона, который у крупных калибров всё ещё может быть смертельным. Отдельного угла брони (`armorScale`) нет. Без центровости (ближний бой `simple`) — полное попадание без крита.

`AimingManager._resolveHitImpacts` для линейного попадания считает `computeHitQuality(centrality)`, кладёт результат в `hit.details.hitQuality` и в `Impact` (`energyScale`, `quality`, `qualityLabel`, `crit`). Если множитель < 1 (или действует спад, или снаряд пришёл после стен, или АоЕ с `effectScale < 1`), урон идёт пакетом `applications` из `ShotManager.buildScaledApplications({ scale, energyScale, base })` — оба множителя режут энергию, урон следует за ней; иначе — снарядом как есть. АоЕ качества не имеет (только `coverage`).

### Спад по дистанции

`ammo.falloff.halfDistance` — расстояние, на котором снаряд сохраняет половину энергии (`falloffMultiplier`, экспонента); урон следует за энергией, пробитие (форма снаряда) не меняется. Считается от дула по прямой (`ShotManager.falloffAt(shot, point)`; `createShot` запоминает `shot.origin` и `shot.falloff` из `penetration.falloff`). Токен без стен на пути получает спад в `energyScale`; стены встречают снаряд уже ослабленным, а остаток после них (`details.carry`) несёт спад до токена (`planWallPasses({ energyAt })`). На АоЕ спад снаряда не действует.

### Пуля, вышедшая из тела

Тело поглощает часть энергии, остальное выходит (`exitApplications`, см. [[ANATOMY_SYSTEM]]). Такая пуля **летит дальше по той же прямой** и ранит следующий токен на линии. Геометрия луча `stop` не меняется — он по-прежнему кончается на первом токене, — но `ShotManager._keepTail` запоминает его **хвост** (`shot.tail`: токены и стены за ним на сегменте по порядку полёта и конец сегмента). Хвост есть только у выстрела со снарядом (`shot.penetration`) и только у линейного сегмента `stop`.

Продолжение считается **после урона**, потому что только он говорит, вышла ли пуля:

1. `_resolveVolleyImpacts` применяет рану первого токена (`_applyWound`); её результат отдаёт `exitApplications` (игрок без прав на цель получает их из ГМ-действия `damage.apply`). Не продолжаются: АоЕ и взрыв, слитая рана залпа (несколько дробин в одной ране), урон, который ждёт ГМа (`queued`) или не применился.
2. `AimingManager._followThrough` → `ShotManager.continueShot` → `followProjectileThroughBodies` (`hit-luck.mjs`, чистая функция). Шаг: стены хвоста проходят через `planWallPasses` с остатком (а не со снарядом из ствола) и уровнем спада, который остаток уже несёт; `walkProjectileCollisions` (`stop`, тот же `judgeToken`: токен, мимо которого пуля пролетает, пропускается и пишется в `shot.passedThrough`) выбирает следующий токен; остаток доводится до него спадом (`спад(B) / спад(A)`), если стены не сделали это раньше (`details.carry`), и идёт в токен как `carry` — поверх него режет энергию качество попадания второй цели, как у любого попадания; `_hitEntry` → `_applyWound` ранит токен (случайная группа и часть), его `exitApplications` кормят следующего.
3. Цепочка кончается там, где пуля осталась в теле, стена её не пропустила, остаток меньше `MIN_CARRY_DAMAGE` (0,005 — меньше сотой не записывается в травму) или кончился сегмент.

Запись об атаке: попадания за первой целью идут в `impacts` луча по порядку, с `through` (имя цели, из которой пуля вышла); у цели, из которой пуля вышла, `exit` — урон остатка («пуля летит дальше: N»). Пролёты мимо и стены за телом попадают в диагностику выстрела (`passes`, `walls`) уже с уменьшенным снарядом.

След: первая запись рисуется сразу, как раньше. Продолжение (от точки выхода через достигнутые тела до стены, остановившей пулю, или до конца сегмента) — **отдельная запись** `shot.extension` (id `<uid>.x`, то же время `t`, то есть тот же ход затухания): `_showExtensions` рисует и рассылает её, когда урон посчитан, а `_collectRay` кладёт в журнал атаки рядом с основной (`records`), поэтому после перезагрузки сцены рисуются обе.

Тесты: `node module/helpers/hit-luck.test.mjs` (порядок, спад, стены, пролёт мимо), `node module/helpers/aiming-hit-quality.test.mjs` (весь путь с настоящим обходом тела: 9×19 остаётся в торсе, .50 BMG вторую цель достаёт; след и журнал).

### Залп и взрыв

- **Залп** (multishot, дробь): лучи одного нажатия сначала создаются все, потом попадания разбираются вместе (`_resolveVolleyImpacts`). Дробины, попавшие в один токен, пока веер у цели не шире `VOLLEY_SHARED_SPREAD` (0,5 ед. сцены), — **одна рана**: один выбор части, пакет из всех дробин (`parallel`), их урон складывается (выстрел в упор попадает в одну часть, а не в ногу и голову сразу). Остальные дробины записаны в журнал «в ту же рану» (`impact.joined`). Дальше каждая дробина — отдельная рана.
- **Взрыв** (`ammo.onHitSplash`: круг помечен `blast`, попадание — `details.blast`): достаёт `BLAST_PART_COUNT` (3) разных частей тела каждой накрытой цели, энергия делится между ними поровну.

Тесты: `node module/helpers/hit-quality.test.mjs` (зоны, падение, настройки), `node module/helpers/aiming-hit-quality.test.mjs` (`_resolveHitImpacts` целиком: энергия, крит, пакет после стен, АоЕ; залп и взрыв), `node module/helpers/weapon/area-coverage.test.mjs` (спад), случай 18 в `damage/damage-resolver.test.mjs` (энергия → урон с бронёй и без).

### Эффект крита режима

Параметр режима огня `critEffect` (`weapon-model.mjs`; редактор режима на листе оружия): `default` — по режиму огня (одиночный — выбор части тела, очередь и авто — ничего), `none`, `pickPart`. `resolveModeCritEffect(mode)` → итоговый эффект; `AimingManager._fireWeaponV3Single` передаёт его в `_resolveHitImpacts` как `critEffect` (у отладочных выстрелов без оружия эффекта нет). Крит — только «яблочко» по цели; фиолетовая зона дуги — другое (крит со стороны стрелка, ещё не сделан).

### Куда попало

Диалога выбора места попадания **нет**: он прерывал бы игру. `_resolveHitImpacts` выбирает группу и часть сам. Крит режима с `pickPart` попадает в группу, помеченную у цели (`system.anatomy.hitGroupOverride`; в записи об атаке — «выбрано: группа»); любое другое попадание (и АоЕ) — случайная группа цели. Часть — случайная в группе (нет групп — случайная часть тела). Заранее выбрать место действием — будущее «Прицелиться» (карточка в Backlog): оно заменит метку на цели.

Строка попадания в чате: «Выстрел N · удар с H ч · центровость X · энергия ×Y (качество)», где «H ч» — положение места удара на циферблате относительно взгляда цели (12 — спереди); у удара без центровости — только «Выстрел N · удар с H ч».

### Уверенность и сопротивление (`shot-confidence.mjs`)

Промах всегда по объективной причине, а не «кубы решили». Касание хитбокса линией — попадание, **если уверенность выстрела больше сопротивления цели**; иначе снаряд пролетает мимо токена и летит дальше (за ним может быть другой токен или стена).

- **Уверенность** — число от зоны дуги, из которой сделан выстрел (`zoneConfidence`, `SHOT_CONFIDENCE_BY_ZONE`): красная 1, оранжевая 2, жёлтая 3, зелёная 5 (4 пропущено намеренно), фиолетовая 6 (выше любого состояния; по умолчанию фиолетовой зоны нет ни у кого). Зона считается один раз на выстрел (`_sampleShotLuck` → `luck.confidence`), все лучи веера используют её.
- **Сопротивление** — число у цели (`computeHitResistance`, `ShotManager._hitResistanceFor`): максимум по состояниям (`HIT_RESISTANCE_STATES`: в бою 1, активно движется 2, в укрытии 3, спрятана за укрытием 5; состояния **не складываются**) плюс плоский модификатор актёра `system.hitResistanceMod` (целое, по умолчанию 0; его меняют эффекты — ActiveEffect ADD на `system.hitResistanceMod`). Не меньше 0. Пока определяется только «в бою» — актёр числится в запущенном бою (`isActorInActiveCombat`, как у пула ОД); остальные состояния ждут карточку «Состояния цели для сопротивления попаданию».
- Выстрел без уверенности (АоЕ-сегменты, отладка, прицеливание не «стандартного» типа) не судится — каждое касание попадание.

Ход: `AimingManager` передаёт `confidence` в `createShot(token, payload, direction, { penetration, confidence })`; `createShot` строит `shot.judgeToken` (`createTokenJudge`), его получают `walkProjectileCollisions(collisions, onHit, shot, wallPlan, { judgeToken })` (`hit-luck.mjs`) в линейном сегменте и в `complexLine`. Токен, мимо которого снаряд пролетел, пропускается до конца выстрела и лежит в `shot.passedThrough` (в `actualHits` его нет, урона нет, `excludeDirectHit` его не исключает из АоЕ); `details` вердикта (`confidence`, `resistance`, `resistanceStates`, `resistanceMod`) остаются и у пролёта, и у настоящего попадания.

Запись об атаке объясняет промах: «Имя · уверенность 1 (красная зона) не выше сопротивления 1 (в бою) — пролетел мимо»; строка зоны в журнале выстрела — «Уверенность: красная зона 1».

Первое настоящее попадание завершает `stop` / `need`; `next` продолжает проникать до стены; стену без материала (или ту, что снаряд не пробил) снаряд не проходит, пробитую — проходит ([[WALL_PENETRATION]]).

Тесты: `node module/helpers/shot-confidence.test.mjs` (таблица зон × состояний, «строго больше», ход по столкновениям), `node module/helpers/hit-luck.test.mjs`.

## Размер цели (хитбокс) и прикрытие

Радиус, в котором снаряд «попадает» по токену, берётся из `ShotManager._targetHitRadius` (радиус токена × `system.hitboxScale` актёра, в процентах); он используется в `_isHitLine` и в расчёте покрытия АоЕ. Базовые характеристики (AGI и др.) на хитбокс **не влияют**. Масштаб хитбокса (обычно ≤ 100%, уклонение) — отдельный параметр листа персонажа. См. `target-size-scaling.md`.

## Заряд: батарея и теплообменник

Боеприпас с `weapon.ammo.charge` (`enabled`, `max`, `current`, `changePerShot`, `changePerSecond`) — не набор патронов, а накопитель. Знак `changePerShot` задаёт вид (`weapon/charge-change.mjs`):

- **Батарея** (`sign: "-"`): `current` — сколько заряда осталось; выстрел тратит; пуста при `current = 0`.
- **Теплообменник** (`sign: "+"`): `current` — накопленное тепло; выстрел греет (`+4` у S), выстрелить можно, пока `current < max`; перегретый (`current ≥ max`) стрелять не даёт, нужен другой холодный.

Общие функции: `chargeGrowsWithShots(charge)`, `chargeSpendableAmount(charge)` (сколько ещё можно потратить: батарея — `current`, теплообменник — `max − current`), `chargeCanFeedShot(charge)`. Их используют `weapon-ammo-runtime.mjs` (готовность блока, подбор запасного накопителя в инвентаре — перегретый не предлагается) и `weapon-model.mjs` (индикатор в HUD показывает остаток, т.е. холодный теплообменник — `40/40`). Тест: `node module/helpers/weapon/charge-change.test.mjs`.

Индикатор патронов в HUD (`buildAmmoDisplay`): `bar` — полоса с засечками (`ammoBarTicks`: до 24 слотов — по засечке на слот, дальше каждые 5 / 10), `pips` — кольца (заряженный слот — кольцо с точкой), `number` — `cur/max`.

## Доступные payloads

Из `manifest.json`:

- `straight-line` — простая линия
