# Размер цели: хитбокс и прикрытие

Файл исторически назывался «масштабирование по DEX». Масштабирования по DEX **больше нет**: базовые характеристики (DEX, END и др.) не влияют ни на размер хитбокса, ни на пробитие. Это наследие раннего прототипа, удалено.

## Два радиуса токена

Оба считаются в `shot-manager.mjs` и нигде больше; все места, где нужен размер цели, берут их оттуда.

| Радиус | Метод | Где используется | Сейчас |
|--------|-------|------------------|--------|
| **Хитбокс (мишень)** | `_targetHitRadius(token)` | попадание линейного снаряда и свинга (`_isHitLine`), центровость, сэмплы покрытия АоЕ | радиус токена |
| **Прикрытие** | `_targetCoverRadius(token)` | токен как препятствие для линии обзора АоЕ (`_checkLineOfSight`) | `0.5 × min(радиус тела, хитбокс)` |

### Хитбокс

`радиус токена × system.hitboxScale / 100`. Масштаб хитбокса — **отдельный параметр листа персонажа** `system.hitboxScale`: целый процент, 100 = размер токена. Обычно ≤ 100% (уклонение уменьшает хитбокс), редко больше. Применяется в одном месте — `_targetHitRadius`. Центровость (`centrality`, см. `NR Попадание по хитбоксу` в Kanban) считается относительно этого радиуса.

- Поле лежит в `template.json` (тип `character`, по умолчанию `100`); у актёров без поля (старые данные, другие типы) масштаб = 100%.
- Нормализация и границы (1–300%) — `module/helpers/hitbox-scale.mjs` (`normalizeHitboxScale`, `hitboxScaleFactor`); тест: `node module/helpers/hitbox-scale.test.mjs`.
- Лист персонажа: вкладка «Характеристики» → группа «Тело и нагрузка» → «Размер хитбокса» (иконка-карандаш открывает диалог).
- Другие источники масштаба (экипировка, эффекты, действия) пока не подключены: параметр читается как есть.

### Прикрытие

Токен прикрывает других от АоЕ не всем хитбоксом, а кругом меньшего радиуса: `TOKEN_COVER_RADIUS_FACTOR` (0.5) × меньший из радиусов «тело» и «хитбокс».

- прикрытие всегда меньше мишени, поэтому взрыв на поверхности цели начинается снаружи её прикрытия, а соседи получают хотя бы частичное покрытие;
- увеличенный хитбокс прикрытие не раздувает, уменьшенный — уменьшает вместе с собой;
- при 0.5 за целью остаётся «тень» шириной ±30° (`sin θ = factor`); коэффициент подбирается на глаз.

Опции АоЕ (`lineOfSight`, `ignoreDirectHitCover`, `excludeDirectHit`, `coverageMode`) описаны в `SHOOTING_SYSTEM.md`, раздел «Покрытие АоЕ».

## Что не считается хитбоксом

- Проверка перекрытия токенов при сортировке в LoS (`_checkLineOfSight`) использует физический радиус токена (границы токена на сцене), а не хитбокс.
- Пробитие не зависит от характеристик цели: `complexLine` не пробивает токены (токен останавливает луч), пробитие брони решает пайплайн урона (`damage-resolver`).
